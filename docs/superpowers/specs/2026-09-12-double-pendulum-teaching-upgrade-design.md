# 双摆模拟器教学升级 — 设计文档

- 日期:2026-09-12
- 状态:已获用户批准(方案 B)
- 项目:`Chaotic Double Pendulum Simulator`
- 用途定位:物理教学演示

## 1. 背景与目标

现有双摆模拟器(Three.js r160 + RK4,零构建静态页)存在以下问题:

1. 物理核心采用**等质量等长**简化方程,质量、杆长各只有一条滑条且被强制相等,无法演示质量比/杆长比对运动的影响;
2. 能量公式与简化模型绑定;
3. "角动量 p"滑条实际是哈密顿广义动量,对学生不直观,且与角速度混用易混淆;
4. 角度显示用 `% 360`,负角度显示不规范;
5. 杆长改变时走 `rebuildPendulum()` 把 4 组 three.js 对象删除重建,浪费且易引入状态残留;
6. 轨迹数组每帧 `splice(0,3)` 搬移全部元素,轨迹长时开销增大;
7. 无数值防护(出现 NaN 时静默黑屏)。

本次升级目标:**物理核心换成通用非对称双摆方程 + 新增"混沌对比"教学模式 + 上述基础修复**。

**非目标**(用户明确排除,不做):能量/相图曲线、分歧-时间对数图、庞加莱截面、预设场景库、倍速/慢放控制、拖拽摆锤设初值。

## 2. 文件结构

保持零构建、Live Server 直接打开的形态:

```
Chaotic Double Pendulum Simulator/
├── index.html                     布局 + 面板(新增"混沌对比"区)+ importmap(不变)
├── physics.js                     纯物理:运动方程、RK4、能量 —— 无 DOM 依赖(新)
├── script.js                      Three.js 场景、摆体渲染、UI 绑定、主循环、对比管理
├── style.css                      现有样式 + 对比模式图例/读数样式
└── tests/
    └── validate_physics.mjs       Node 直跑的物理验证脚本(不参与页面发布)
```

拆出 `physics.js` 的理由:验证脚本可在 Node 中直接 `import` 纯函数,无需浏览器。

代码内部结构:

- `Pendulum` 类:状态 (θ₁, θ₂, ω₁, ω₂) + 轨迹缓冲 + 3 组 three.js 对象(杆×2、锤×2),可实例化 A/B 两份;
- `ComparisonManager`:对比模式的 A/B 协调(创建 B、施加 δ、重新同步、销毁);
- 主循环:保持 rAF + 固定子步,新增子步上限。

## 3. 物理核心

### 3.1 运动方程

采用通用非对称双摆的角加速度形式(θ 从竖直向下量起,与现有坐标约定 x = L sinθ、y = −L cosθ 一致):

```
α₁ = [ −g(2m₁+m₂)sinθ₁ − m₂g sin(θ₁−2θ₂)
       − 2sin(θ₁−θ₂)·m₂·(ω₂²L₂ + ω₁²L₁cos(θ₁−θ₂)) ]
     / [ L₁(2m₁ + m₂ − m₂cos(2θ₁−2θ₂)) ]

α₂ = [ 2sin(θ₁−θ₂)·(ω₁²L₁(m₁+m₂) + g(m₁+m₂)cosθ₁ + ω₂²L₂m₂cos(θ₁−θ₂)) ]
     / [ L₂(2m₁ + m₂ − m₂cos(2θ₁−2θ₂)) ]
```

分母 2m₁+m₂−m₂cos(2Δθ) ∈ [2m₁, 2m₁+2m₂],对正质量恒为正,无奇点。

- 状态量:**(θ₁, θ₂, ω₁, ω₂)**(角速度形式),替换现有的 (θ₁, θ₂, p₁, p₂) 正则动量形式;
- 积分器:RK4 保留,固定 dt = 0.002,按帧时长补子步;**新增每帧子步上限**(如 100 步,标签页后台返回时钳制单帧模拟时长,避免卡顿);
- UI:质量 m₁、m₂ 独立滑条,杆长 L₁、L₂ 独立滑条;"角动量 p"滑条改为"**角速度 ω₁/ω₂(rad/s)**"。

### 3.2 能量

```
T = ½(m₁+m₂)L₁²ω₁² + m₂L₁L₂ω₁ω₂cos(θ₁−θ₂) + ½m₂L₂²ω₂²
V = −(m₁+m₂)gL₁cosθ₁ − m₂gL₂cosθ₂
E = T + V
```

### 3.3 数值防护

每步后检查状态有限性:任一状态量非有限值 → 自动暂停 + 面板提示"数值发散,请重置"。

## 4. 混沌对比模式(核心新功能)

### 4.1 面板控件(新增"混沌对比"区)

| 控件 | 说明 |
|---|---|
| 对比模式开关 | checkbox,默认关 |
| 初始差值 δ | number 输入,默认 0.1;单位跟随施加变量:角度变量为度(内部转弧度),ω 变量为 rad/s |
| 施加变量 | 下拉:θ₁ / θ₂ / ω₁ / ω₂,默认 θ₁ |
| 重新同步按钮 | 把 B 置为"A 当前状态 + δ" |
| 实时读数 | \|Δθ₁\|、\|Δθ₂\|(度;< 0.001° 时显示科学计数) |

### 4.2 视觉设计

- B 摆与 A 摆叠加在同一 3D 场景:A 保持现有配色(摆锤橙/蓝),B 用绿/紫;
- 两摆的末端轨迹并排渐隐,初值分裂导致的轨迹分离直接可见;
- 面板加 A/B 图例(颜色对应)。

### 4.3 行为规则

- B 摆参数与 A 完全相同:m/L 滑条同时作用于两摆;
- B 摆初值 = A 初值复制后,在选中变量上加 δ;
- 初值滑条(θ₁/θ₂/ω₁/ω₂)保持现有行为:仅暂停时可调,此时 B 自动跟随(保持 δ);
- 对比模式开启时修改 δ 或施加变量 → 自动重新同步 B 并清空 B 轨迹(A 不受影响);
- 播放中改参数 → 同样作用于两摆并清空双方轨迹;
- 关闭对比模式 → 从场景移除 B 的对象并释放 geometry,读数区隐藏;
- 重置按钮 → A/B 均回到各自初始状态。

## 5. 基础修复清单

1. 角度显示规范化到 (−180°, 180°];
2. 杆长/质量改变只更新几何数据与位置,**不删除重建** three.js 对象;
3. 轨迹缓冲改为预分配环形缓冲(容量 = maxTrailPoints),替换 `splice` 搬移;
4. NaN 防护(见 3.3);
5. 触屏核查:OrbitControls 自带触摸旋转;滑条为原生控件天然支持触摸;补小屏 CSS 细节(面板宽度、读数区换行);
6. 能量读数、运行时间显示与现状保持一致(数值来源换成新公式)。

## 6. 验证(物理正确性)

`tests/validate_physics.mjs`(Node 运行,`node tests/validate_physics.mjs`):

1. **平衡态**:θ₁=θ₂=0 与 θ₁=θ₂=π、ω=0 → 导数幅值 < 1e-12(容差容纳 -0);
2. **逐点能量相容**:中心差分 dE/dt = ∇E·(dx/dt) 在随机状态残差 < 1e-5 —— 运动方程与能量公式转录一致性的直接闸门(实测噪声 ~3e-7);
3. **能量守恒**:混沌初始条件(θ₁=120°, θ₂=−10°, ω=0)、dt=0.0005 积分 60 秒,相对能量漂移 |ΔE/E₀| < 1e-6(实测 3.9e-8)。生产页面 dt=0.002 下 60s 实测漂移 ~4e-5,属 RK4 正常截断,能量面板 3 位小数下不可见;
4. **小角度极限**:m₁=m₂、L₁=L₂=L、小角度释放,周期 ≈ 2π√(L/g)(误差 < 2%,实测 2.0080 vs 2.0071)。

验收时同样在浏览器人工核对:能量读数长时间稳定、对比模式 0.1° 初值差约 10–30 秒内轨迹肉眼可见分裂。

## 7. 验收标准

1. m₁≠m₂、L₁≠L₂ 可独立调节,小角度单摆极限周期符合理论值;
2. 能量相对漂移 60 秒 < 1e-6(验证脚本 dt=0.0005),生产 dt=0.002 实测 ~4e-5,面板能量读数稳定;
3. 对比模式:δ=0.1° 时 10–30 秒内轨迹可见分裂,|Δθ| 读数持续增长;
4. 角度显示无负零/越界;参数调整不触发对象重建;
5. 触屏可完成:旋转视角、调参、播放/暂停/重置、开关对比模式;
6. 零构建保持:`node tests/validate_physics.mjs` 直接通过;页面 Live Server 打开即用。

## 8. 风险与对策

- **方程转录错误**:以能量守恒验证(6.2)兜底,能量漂移超标即说明方程或符号有误;
- **RK4 长期漂移**:教学演示时长(分钟级)内 1e-6 漂移足够;若实测不达标,优先减小 dt 而非换积分器;
- **UI 改动破坏现有布局**:新增区独立成块,不动现有控件结构。
